# コードコメントの棚卸し

対象リポジトリの指示と除外条件を確認し、用語集と対象領域の ADR があればコードを読む前に参照する。対象パスはそのリポジトリ内に限定し、未指定なら現在の Git リポジトリを対象にする。コミットを指定された場合は解決した SHA、既定では HEAD の SHA を使う。棚卸しは読み取り専用で、処置案を報告して終了する。コメントの削除、ADR、Issue、lint の変更はそれぞれ明示的な依頼を受けてから行う。

## コメントを列挙する

対象版の追跡済みソースから、対象パスと除外条件に合う通常ファイルを列挙する。生成物や第三者コードは対象リポジトリの指示を踏まえて除外する。ファイルを実行せず、言語ごとの構文解析器でコメントの範囲を取得する。抽出コマンドが必要なら [コメント抽出の手順](references/extraction.md) を読む。文字列中のコメント記号は、構文解析でコメントと判定された箇所だけを数えることで除く。解析器がない言語や解析に失敗したファイルは、対象と理由を報告する。

## 処置案を決める

コメントごとに周辺コードを読み、判断に必要なテストや既存の文書を照合する。

| 見つけた内容                               | 処置案                                                                                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| コードの言い換え、または実態と食い違う説明 | 削除。陳腐化は現行の根拠を確認してから判定する                                                                   |
| 暫定実装の理由                             | 挙動、影響、修正後の受入条件を後続 Issue の案として記す                                                          |
| コードだけでは読み取れない判断理由         | 保持、または既存の ADR など正本へ集約する。変更の費用が大きく、実際に選択肢を比較した判断は新規 ADR の候補にする |
| ツール指示、ライセンス、機械処理される注釈 | 保持し、何が利用しているか示す                                                                                   |
| 根拠が不足している説明                     | 保留し、確認先を示す                                                                                             |

## 報告する

コミット SHA、対象パス、解析コマンド、解析ファイル数、コメント件数、コメントが占める物理行の数を記す。除外や解析不能の範囲を示し、各コメントにファイルと行、処置案、根拠を付ける。

コメントの件数と、実際に消えるソース行を分ける。削除候補と文書へ移す候補の削減見込みを示し、同じ行は一度だけ数える。コードが同じ行に残る場合は削減を 0 行とする。lint を提案する場合は、既存コメントを許容して新規追加を検査する基準と、ツール指示などの例外を記す。
